# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Beat The Scam (https://beatthescam.com) is a UK consumer-protection site: plain-English scam guides + a free AI scam checker. It is a **bespoke Python static-site generator** — not Next.js, Hugo, or Jekyll. The entire site is generated by `scripts/build.py` reading JSON content and rendering through one HTML template into `dist/`. The only dynamic surface is a single Netlify Function that proxies the AI checker to the Anthropic API.

## Commands

```bash
pip install -r requirements-claude.txt   # one-time deps (build needs only stdlib + optional Pillow/minifiers)

python3 scripts/build.py                  # rebuild the whole site into dist/ (run from repo root)
```

There is **no test suite and no linter**. The build is the verification step. The CI pipelines sanity-check a build by asserting `dist/index.html`, `dist/robots.txt`, `dist/_redirects` exist and `dist/guides/` has ≥50 subdirectories — do the same locally after changing `build.py`.

Content / pipeline scripts (all need `ANTHROPIC_API_KEY` and write to `content/posts.json`, then you rebuild):

```bash
# Generate guides from the queue (orchestrator used by CI)
python3 scripts/run_daily_publish.py --queue content/daily-publish-queue.csv \
  --topics content/topics-claude-template.csv --posts content/posts.json \
  --batch-size 1 --model claude-haiku-4-5-20251001

# Lower-level generator (one CSV → posts.json)
python3 scripts/generate_content_claude.py content/daily-publish-queue.csv \
  --posts content/posts.json --mode claude --model claude-haiku-4-5-20251001

python3 scripts/rewrite_thin_guides.py --posts content/posts.json --threshold 400 --limit 10
python3 scripts/generate_video.py <slug>        # render MP4 → out/videos/ (gitignored)
python3 scripts/upload_to_youtube.py <slug>     # upload Short (Unlisted; --public to publish)
python3 scripts/tweet_new_articles.py --slug <slug>
```

## Architecture

**The build pipeline IS the application.** `content/posts.json` + `content/site.json` + `content/affiliates.json` → `scripts/build.py` → `dist/`. `templates/base.html` is the single page shell; `make_base()` fills its `{{placeholder}}` tokens. Page renderers (`render_home`, `render_post`, `render_category_page`, `render_check_page`, …) build HTML strings, and `build()` at the bottom of `build.py` orchestrates everything and writes every file in `dist/`.

**`dist/` is committed to git AND is exactly what Netlify serves** — there is no build step on Netlify (build command is blank). Consequences:
- A content/template/style change only goes live once you run `python3 scripts/build.py` **and commit the regenerated `dist/`**. Pushing source without rebuilding ships nothing.
- **Never hand-edit anything in `dist/`** — `build()` regenerates the entire directory (it `rmtree`s `dist/` first). This includes `_redirects`, `robots.txt`, `sitemap.xml`, `rss.xml`, `search.json`, `ads.txt`, `llms.txt`, `humans.txt`, `.well-known/security.txt`, `404.html`, and per-post OG images.

**Post schema** — each object in `content/posts.json`: `slug`, `title`, `description`, `hero`, `date` (`YYYY-MM-DD`), `category`, `keywords` (list), `sections` (list of `[heading, body]` pairs), `faq` (list of `[question, answer]` pairs). `posts.json` is the single source of truth; categories, schema, related guides, search index, and sitemap all derive from it.

**Categories are driven by three dicts at the top of `build.py`**: `CATEGORY_CANON` (raw label → canonical slug normalisation), `CATEGORY_LABELS` (slug → display name), `CATEGORY_DESCRIPTIONS`. To add/rename/merge a category, edit these — do not touch rendered output. `CATEGORY_CANON` also auto-emits the category 301s in `dist/_redirects`.

**Redirects are split across two mechanisms (important gotcha):** `netlify.toml` `[[redirects]]` blocks do **not** apply at the edge here except the `/api/check-scam` → function rewrite (status 200) and the `/*` → `404.html` catch-all. All **category and article 301s must live in `dist/_redirects`**, which `build()` auto-generates from `CATEGORY_CANON` and the `ARTICLE_REDIRECTS` dict (maps a dead slug → replacement slug, or `__CAT__:<cat>` → category page). When you delete/rename a guide, add its old slug to `ARTICLE_REDIRECTS` so inbound links 301 instead of 404.

**The AI scam checker** (`netlify/functions/check-scam.js`) is the only server-side code. It is a hardened proxy to the Anthropic API: in-memory per-IP rate limiting (10/min), origin allow-listing, input length caps, verdict/confidence enum validation, and `https://`-only reporting links. It reads `ANTHROPIC_API_KEY` from Netlify env and uses model `claude-haiku-4-5-20251001` (same model as content generation). The page calls it via the `/api/check-scam` rewrite.

**Two scheduled content pipelines** (`.github/workflows/`): `daily-publish.yml` (05:07 UTC, generates from the queue) and `daily-search-console.yml` (05:23 UTC, fills Search Console content gaps). Both: call Claude → append to `posts.json` → `build.py` → commit `dist/` → push → auto-tweet. They are serialised via a shared `concurrency: content-pipeline` group because both regenerate `sitemap.xml` from `posts.json`. Each has a rebase-conflict recovery path that snapshots `content/*`, hard-resets to `origin/main`, re-merges posts **by slug** via `scripts/merge_new_posts.py` (never merging `dist/`, since it is derived), and rebuilds.

## Deploy

Push to `main` → Netlify auto-deploys `dist/` (~30s). The Netlify publish directory must be set to `dist` **in the dashboard**, not just `netlify.toml`. `netlify.toml` owns the security headers — note the CSP intentionally allows `'unsafe-inline'` in `script-src` because GA4 and AdSense inject inline scripts; do not "tighten" it without removing those.

## Where to look

Canonical docs live in `docs/`. **`docs/project.md` is the master source-of-truth** (tech stack, secrets inventory, monetisation, SEO, security, runbook, known gotchas — Section 20 is the gotcha log). `docs/next-session.md` is the fast-start front door. `docs/video-pipeline.md` and `docs/daily-publish.md` cover those subsystems. Secrets live in `.env` (gitignored, local) and GitHub/Netlify env — `.env.example` documents the keys.
